## 四、坐标数字大小不随缩放变化

### 问题描述
缩放画布时，网格坐标数字也跟着变大缩小。

### 解决方案
不修改 painter 的变换矩阵，而是反向缩放字体大小：

```cpp
double scale = max(|transform.m11|, |transform.m22|);
font.setPixelSize(9.0 / scale);  // 屏幕上始终约 9px
```

### 修改文件

#### `render/GridScene.cpp` — `drawForeground()` 重写
- 完全改用像素大小（`setPixelSize`）+ 反比缩放，保持 painter 变换矩阵不动
- X 轴标签（底部）：始终约 9px 字体
- Y 轴标签（左侧）：始终约 9px 字体
- 缩放时数字大小不变

## 五、测试模式移动速度调整

### 问题描述 1：瞬移
切换队形时无人机"瞬移"——`speed = 3.0` 米/100ms = 30m/s，在 5m 间距下 0.2~0.7 秒就到达目标。

### 问题描述 2：先快后慢
刚切换时无人机扎堆，分离力叠加导致总速度远超基础速度，散开后力变小，速度不一致。

### 最终方案（速度归一化）
在 `onTimerTick()` 中保存每帧旧位置，目标移动 + 分离力计算完成后，将总位移归一化到 `speed`：
- 分离力只影响**方向**，不再影响**速度大小**
- 每帧每架无人机严格移动 `speed = 1.0` 米，速度恒定

### 修改文件

#### `test/TestStateReceiver.cpp`
- `speed = 3.0` → `speed = 1.0`（10 m/s）
- 新增：帧初保存 `oldX/oldY`，帧末归一化总位移至 `speed`

#### `test/TestStateReceiver.h`
- `MIN_SEPARATION = 15.0` → `4.0`
- `SEPARATION_STRENGTH = 10.0` → `1.0`

## 六、急停 / 降落行为修正

### 问题描述
- **急停**：无人机 `continue` 跳过主动移动，但 `applySeparation()` 仍把它推开，导致"往回飞"
- **降落**：`y -= 2.0` 后被 `applySeparation` 推动，再被速度上限 `speed=1.0` 砍残，下降不到 2 米，看起来像短暂停顿后继续漂移

### 修复方案
`applySeparation()` 和速度上限循环中，跳过 `m_faultDrone` / `m_landingDrone` / `m_landedDrone`：
- 急停无人机：完全静止，不被任何力推动
- 降落无人机：以 2.0m/tick 恒速下降，不受分离力和速度上限干扰

### 问题根因（补充）
**UI 按钮从未真正触发 TestStateReceiver！** `onEmergency()` 和 `onLand()` 只调用了 `setLatestCmdId(cmdId)`，它只传了一个 `uint32_t` ID，没传 `cmd_type`。TestStateReceiver 完全不知道按钮点击了什么。用户观察到的"急停/降落"行为来自硬编码在 tick 30/40/60 的测试事件。

### 补充修复
1. `TestStateReceiver` 新增 `triggerEmergencyStop()` 和 `triggerLanding()` 方法
2. `MainWindow::onEmergency()` 调用 `m_testReceiver->triggerEmergencyStop()`
3. `MainWindow::onLand()` 调用 `m_testReceiver->triggerLanding()`
4. 这两个方法设置所有活跃无人机的 `m_faultDrone` / `m_landingDrone` 标志，并清除互斥标志

### 修改文件

#### `test/TestStateReceiver.cpp`
- `applySeparation()` — 跳过条件增加 `m_faultDrone[i] || m_landingDrone[i] || m_landedDrone[i]`
- 速度上限循环 — 同上
- 新增 `triggerEmergencyStop()` — 所有活跃无人机急停
- 新增 `triggerLanding()` — 所有活跃无人机开始降落

#### `test/TestStateReceiver.h`
- 新增 `triggerEmergencyStop()` 和 `triggerLanding()` 声明

#### `MainWindow.cpp`
- `onEmergency()` — 新增调用 `m_testReceiver->triggerEmergencyStop()`
- `onLand()` — 新增调用 `m_testReceiver->triggerLanding()`

## 七、失联无人机渲染修复

### 问题描述
无人机 ST_LOST 后，渲染界面只冻结不动、不消失。原因是 `updateDroneDisplay()` 只过滤了 `ST_LANDED`，没有过滤 `ST_LOST`。失联状态被缓存在 `DroneStateCache` 中永远不淘汰，导致 `activeIds` 始终包含该无人机，清理循环永不删除。

### 修复方案
在 `updateDroneDisplay()` 中同步过滤 `ST_LOST`。

### 修改文件

#### `MainWindow.cpp`
- `if (state.status == DroneStatus::ST_LANDED) continue;`
- → `if (state.status == DroneStatus::ST_LANDED || state.status == DroneStatus::ST_LOST) continue;`
