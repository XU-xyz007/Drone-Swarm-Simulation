## 二、A 下发的命令

A 通过 DDS 发送 `DroneCmd`，字段如下：

| 字段 | 类型 | A 填充的值 |
|------|------|-----------|
| `cmd_id` | `uint32_t` | 自增计数器，从 1 开始 |
| `cmd_type` | `DroneCmdType` | 见下表 |
| `formation_id` | `uint32_t` | 0=方阵, 1=一字, 2=三角, 3=圆 |
| `formation_text` | `string` | 当前为空 |
| `target_x` | `double` | 队形中心 X（米），UI 面板输入 |
| `target_y` | `double` | 队形中心 Y（米），UI 面板输入 |
| `spacing` | `double` | 间距（米），UI 面板输入 |
| `expected_count` | `uint32_t` | 无人机总数 N，UI 面板输入 |

### A 的 4 个按钮对应命令

| 按钮 | `cmd_type` | 说明 |
|------|-----------|------|
| 起飞 | `CMD_TAKEOFF (0)` | 起飞 |
| 切换队形 | `CMD_FORMATION (1)` | 切换编队队形 |
| 降落 | `CMD_LAND (2)` | 降落 |
| 急停 | `CMD_EMERGENCY (3)` | 紧急停止 |

## 三、A 读取的状态字段

A 收到 `DroneState` 后，只读取以下 5 个字段：

| 字段 | A 的用途 |
|------|----------|
| `drone_id` | 识别无人机，关联缓存和图形项 |
| `x` | 画布横坐标（米） |
| `y` | 画布纵坐标（米） |
| `status` | 决定画布颜色 + 参与队形完成判定 |
| `current_cmd_id` | 参与队形完成判定 |

---

## 四、A 的颜色映射

A 根据收到的 `status` 字段，按以下规则渲染无人机颜色：

| `status` | A 画布颜色 | RGB |
|----------|-----------|-----|
| `ST_IDLE (0)` | 绿色 | `(76, 175, 80)` |
| `ST_TAKEOFF (1)` | 琥珀色 | `(255, 193, 7)` |
| `ST_CRUISE (2)` | 黄色 | `(255, 235, 59)` |
| `ST_LANDING (3)` | 蓝色 | `(33, 150, 243)` |
| `ST_LANDED (4)` | 紫色 | `(156, 39, 176)` |
| `ST_FAULT (5)` | 红色 | `(244, 67, 54)` |
| `ST_LOST (6)` | 灰色 | `(128, 128, 128)` |

## 五、A 的队形完成判定公式

A 每 200ms 检测一次，同时满足两个条件则弹窗"编队完成！"：

```
条件 1：所有 N 架无人机都经历了 ST_CRUISE → ST_IDLE 的状态过渡
条件 2：所有 N 架无人机的 current_cmd_id == A 最近下发的 cmd_id
```

### 判定流程

```
A 发送 CMD_FORMATION (cmd_id=K)
    ↓
A 收到 ST_CRUISE → 记录"此无人机正在移动"
    ↓
A 收到 ST_IDLE → 检测到 CRUISE→IDLE 过渡，标记"此无人机已完成"
    ↓
全部 N 架完成过渡 + 全部 current_cmd_id == K
    ↓
弹窗 "编队完成！"
```

## 六、A 的 UI 约定

### 6.1 画布

| 项目 | A 的约定 |
|------|----------|
| 坐标系 | 米制，原点在画布中央 |
| 渲染频率 | 20 Hz（50ms） |
| 首次渲染 | 自动 fitInView 适配视野 |
| 用户交互 | 滚轮缩放、拖拽平移 |
| 最小场景 | 400×400 米 |

### 6.2 参数面板

| 参数 | 范围 | 默认值 |
|------|------|--------|
| 无人机数量 N | 1 ~ 200 | 8 |
| 队形类型 | 0=方阵, 1=一字, 2=三角, 3=圆 | 0 |
| 中心 X | 任意 double | 0.0 |
| 中心 Y | 任意 double | 0.0 |
| 间距 | 任意 double（>0） | 5.0 |
