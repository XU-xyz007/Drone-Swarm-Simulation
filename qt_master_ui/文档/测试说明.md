# 压力测试说明文档

> 版本：v1.0 | 创建：2026-09-02 | 用于测试主控端在高负载下的消息处理能力与渲染性能

---

## 一、测试概述

压力测试模块用于验证主控端在以下场景下的表现：

| 测试维度 | 说明 |
|----------|------|
| **消息吞吐量** | 模拟大量无人机同时上报状态，验证 `DroneStateCache` 和 `FormationChecker` 的锁性能 |
| **渲染帧率** | 验证 50ms 渲染循环在大量 `DroneItem` 时的表现 |
| **高频更新** | 模拟 50Hz 状态更新，验证回调处理速度 |
| **多状态渲染** | 同时存在急停/降落/就位/巡航多种状态，验证颜色切换 |
| **队形切换压力** | 自动循环切换队形，验证 `FormationChecker` 判定和 UI 进度更新 |

### 运动模式说明

| 模式 | 行为 | 测试重点 |
|------|------|----------|
| 随机游走 | 每帧随机偏移，范围受速度控制 | 基础渲染压力 |
| 圆形轨道 | 每架无人机在不同半径的圆上运动 | 均匀分布渲染 |
| 正弦波 | 水平移动 + 正弦波垂直偏移 | 规律性平滑移动 |
| Z形折线 | 45° 折线往返 | 方向突变时的拖影 |
| 队形循环 | 自动在方阵/一字/三角/圆之间切换 | 队形判定 + 目标计算 |

### 特殊状态注入

- **tick=60**：注入 10% 急停无人机（红色）
- **tick=120**：注入 10% 降落无人机（灰色，向下移动直到消失）

## 三、如何测试

### 启动方式

1. 编译运行程序
2. 在左侧面板找到 **"压力测试"** 分组
3. 从下拉框选择一个预设场景
4. 观察画面和状态栏

### 观察指标

| 指标 | 位置 | 说明 |
|------|------|------|
| 画面流畅度 | 主画布 | 无人机移动是否卡顿 |
| 拖影效果 | 主画布 | 飞行轨迹是否连续 |
| 消息速率 | 压力测试面板 | 实际消息 FPS |
| 队形进度 | 状态栏 | 自动队形时的完成进度 |
| 终端日志 | 控制台 | 消息统计和事件日志 |

### 测试步骤建议

**基础测试：**
1. P1 → 确认画面正常，作为基线
2. P2 → 确认 50 架无卡顿
3. P3 → 确认 100 架可接受
4. P4 → 观察 200 架是否明显掉帧

**高频测试：**
5. P5 → 50 架 50Hz，确认渲染正常
6. P6 → 100 架 50Hz，观察是否掉帧
7. P7 → 200 架 50Hz，极限压力

**特殊运动测试：**
8. P8 → 高速移动，观察拖影是否连续
9. P9 → 圆形轨道，观察排列是否均匀
10. P10 → 波浪运动，观察正弦波平滑度
11. P11 → 折线运动，观察方向突变

**队形测试：**
12. P12 → 50 架自动队形切换，观察完成判定
13. P13 → 120 架密集队形，观察判定压力
14. P15 → 200 架极限队形

**多状态测试：**
15. P14 → 运行约 12 秒后出现急停和降落无人机

## 四、预期结果

### 正常表现

| 场景 | 预期 |
|------|------|
| P1~P3 | 画面流畅，无卡顿，FPS ≥ 55 |
| P4 | 可能有轻微卡顿，FPS ≥ 40 |
| P5 | 高频消息正常处理，FPS ≥ 50 |
| P6~P7 | 可能出现掉帧，FPS ≥ 30 |
| P8 | 高速移动拖影连续，FPS ≥ 55 |
| P9~P11 | 特殊运动轨迹清晰，FPS ≥ 55 |
| P12~P13 | 队形自动切换，进度正常更新 |
| P14 | 12 秒后出现红色和灰色无人机 |
| P15 | 极限压力，FPS ≥ 30 |

### 异常表现

| 现象 | 可能原因 |
|------|----------|
| 画面卡死 | 渲染循环阻塞 |
| FPS 急剧下降 | 消息量超过渲染能力 |
| 进度不更新 | 状态判定逻辑问题 |
| 颜色异常 | 状态枚举映射错误 |
| 程序崩溃 | 数据竞争或内存不足 |

### 压力测试面板颜色含义

- **绿色**：当前 FPS ≥ 预期最低 FPS（通过）
- **红色**：当前 FPS < 预期最低 FPS（不达标）

## 五、测试数据详解

### 消息量计算

| 预设 | 每秒消息数 | 每帧渲染点数 |
|------|-----------|-------------|
| P1 | 100 | 10 |
| P2 | 500 | 50 |
| P3 | 1,000 | 100 |
| P4 | 2,000 | 200 |
| P5 | 2,500 | 50 |
| P6 | 5,000 | 100 |
| P7 | 10,000 | 200 |
| P12 | 500 | 50 |
| P13 | 1,200 | 120 |
| P15 | 4,000 | 200 |

### 锁竞争分析

在高频场景（P5~P7）中：
- `DroneStateCache::updateState()` 每秒被调用 2,500~10,000 次
- 渲染循环 `getAllStates()` 每秒被调用 20 次
- 两个操作共享 `m_mutex`，锁竞争频率极高

### 内存占用估算

| 无人机数 | DroneState 大小 | 总内存（约） |
|----------|----------------|-------------|
| 10 | ~64 bytes | 640 B |
| 50 | ~64 bytes | 3.2 KB |
| 100 | ~64 bytes | 6.4 KB |
| 200 | ~64 bytes | 12.8 KB |

> 加上 `DroneItem`、轨迹缓存等，200 架无人机总内存约 2~5 MB。
